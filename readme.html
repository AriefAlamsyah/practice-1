STEP 0

What you need

Only two free things:

  • A text editor: a program for writing code. We recommend VS Code. (Even Notepad works, it's just less comfortable.)
  • A web browser: Chrome, Edge or Firefox. You already have one.

That's it. No installing, no servers, no accounts.

STEP 1

The big idea: HTML & CSS

Think of a website like a person:

LanguageLike a person's…What it does
HTMLBody / skeletonSays what is on the page: a title, a paragraph, a button, a picture.
CSSClothes & makeupSays how it looks: colors, sizes, spacing, where things sit.

HTML is written with tags. A tag is a word inside pointy brackets. Most tags come in pairs: an opening one and a closing one (with a /). Whatever is between them is the content.

<h1>Hello!</h1>          ← a big title
<p>I am a paragraph.</p>   ← normal text
<a href="layanan.html">Go to Layanan</a>   ← a link

CSS picks something on the page and gives it "rules":

h1 {
  color: blue;        ← make every h1 blue
  font-size: 40px;    ← and big
}

💡 Class = a name tag. In HTML we write class="btn", and in CSS we style it with .btn { … } (the dot means "class"). Every element wearing that name tag gets the same look.

STEP 2

Read the plan first

Before writing any code, we read the website plan (the "3-Page Website Plan" document). It already told us:

  • 3 pages: Beranda (Home), Layanan (Services), Tentang & Kontak (About & Contact).
  • The sections of each page, from top to bottom, with the exact Indonesian text.
  • Things on every page: the top menu, the footer, and a floating WhatsApp button.
  • The look: white background, soft black and warm off-white colors, the font "Plus Jakarta Sans", designed for phones first.

💡 Having a plan is like having a recipe before cooking. Coding becomes "just follow the steps".

STEP 3

Make the folder & files

We made one folder and put these files inside:

practice-1/ ├── index.html ← Page 1: Beranda (the home page) ├── layanan.html ← Page 2: Layanan & Portofolio ├── tentang.html ← Page 3: Tentang Kami & Kontak ├── readme.html ← this guide you are reading └── css/ └── style.css ← ONE style file shared by all 3 pages

Why index.html? Because browsers and web hosts automatically open the file called index.html first. It's the "front door".

Why only one CSS file? So that if you change a color once, it changes on all three pages. Less work, and everything matches.

STEP 4

The empty page "skeleton"

Every HTML page starts with the same few lines. Here they are, with what each one means:

<!DOCTYPE html>                 ← "Hi browser, this is a modern web page"
<html lang="id">               ← start of page; "id" = Indonesian language
<head>                         ← invisible info ABOUT the page
  <meta charset="UTF-8">       ← lets us use all letters & symbols (–, ✓, é)
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
                               ← "fit the phone screen" (very important!)
  <title>...</title>           ← text shown on the browser tab & in Google
  <meta name="description" content="...">  ← short summary for Google
  <link rel="stylesheet" href="css/style.css">  ← "wear these clothes"
</head>
<body>                         ← everything you SEE goes in here
  ...
</body>
</html>

Inside <body>, we split the page into three big parts:

<header> ... </header>   ← the menu at the top
<main>   ... </main>     ← the real content (all the sections)
<footer> ... </footer>   ← the dark area at the bottom

✋ Try it: open index.html in VS Code and look for <header, <main> and <footer. Notice the comments like <!-- 1. HERO -->. Comments are notes for humans; the browser ignores them.

STEP 5

Choose colors once ("paint cans")

At the very top of css/style.css, we saved our colors with names. Think of them as labelled paint cans:

:root {
  --brand:  #222222;   ← charcoal (soft black): links, icons
  --accent: #222222;   ← charcoal: the buttons we want people to click
  --bg:     #fbfaf8;   ← warm off-white page background
  --tint:   #f2f0ec;   ← slightly darker warm white, for section backgrounds
  --text:   #262626;   ← soft black, for text
  --wa:     #25d366;   ← WhatsApp green
}

Then everywhere else, instead of writing the color code, we just say "use the brand paint":

.btn-primary { background: var(--accent); }

Why black and white, and how we made it easy on the eyes

Black and white are each other's opposite (their complement), so together they give the strongest, cleanest look. It feels modern and premium, like a fashion or design studio. But pure black (#000000) on pure white (#ffffff) is very harsh to read for a long time. It's like staring at a bright screen in a dark room. So we softened both:

  • Charcoal (#222222) instead of pure black, for buttons and the closing band.
  • Soft black (#262626) for text: still very dark, but gentler.
  • Warm off-white (#fbfaf8) instead of pure white for the page. A tiny bit of warmth (like paper) feels calmer than cold blue-white.
  • Warm greys in between, for borders, small text and backgrounds, so the jump from dark to light is never too sudden.

The only "real" color left is the WhatsApp green on the floating button, because people recognise it instantly. We also checked the contrast: every text color is still dark enough on its background to read easily.

✋ Try it: change --accent: #222222; to --accent: #7c3aed; (purple), save, and refresh the browser. Every main button on all 3 pages turns purple! Change it back afterwards.

We also set the font, the text size (17px, easy to read), and a .container class: an invisible box that keeps content in the middle of the screen with 16px of space on each side, so text never touches the edge of a phone.

STEP 6

The menu at the top

The menu has the logo, three links, and a "Hubungi Kami" button:

<header class="header">
  <nav class="container nav">
    <a href="index.html" class="logo">[Nama Agensi]</a>
    <label for="menu-toggle" class="menu-icon">☰</label>   ← only visible on phones
    <ul class="nav-links">
      <li><a href="index.html">Beranda</a></li>
      <li><a href="layanan.html">Layanan</a></li>
      <li><a href="tentang.html">Tentang Kami</a></li>
      <li class="nav-cta"><a href="tentang.html#kontak" class="btn btn-primary">Hubungi Kami</a></li>
    </ul>
  </nav>
</header>

Notice the "Hubungi Kami" button is the last item of the list, together with the links. So on a phone it hides inside the ☰ menu with the others (as a full-width button at the bottom), and on a laptop it sits at the end of the menu row.

Fixed: in CSS we wrote position: fixed; top: 0; on the header. That means "glue this to the top of the screen, no matter how far you scroll". Because a fixed menu floats on top of the page, we also pushed the page down by the menu's height, so the menu doesn't cover the first lines:

.header { position: fixed; top: 0; left: 0; right: 0; }
body    { padding-top: 4.2rem; }   ← same as the menu's height

Logo always left, ☰ always right: the menu row is a grid with 2 columns. The logo gets "all the free space" and the ☰ gets "only what it needs". So even on a tiny screen they stay on one line. If the logo is too long, it ends with "…" instead of pushing the ☰ down:

.nav  { display: grid; grid-template-columns: minmax(0, 1fr) auto; }
                                         ↑ logo        ↑ ☰
.logo { white-space: nowrap; text-overflow: ellipsis; overflow: hidden; }

The ☰ "hamburger" on phones: phones are too narrow for all the links, so we hide them behind a ☰ button. Normally that needs JavaScript, but we used a trick with a hidden checkbox (the little tick box from forms):

<input type="checkbox" id="menu-toggle" class="menu-toggle">  ← hidden tick box
...
<label for="menu-toggle">☰</label>    ← tapping ☰ ticks the box
.nav-links { display: none; }                         ← links hidden at first
.menu-toggle:checked ~ .nav-links { display: block; } ← box ticked? show links!

💡 display: none = invisible and takes no space. display: block = visible. A lot of "interactive" CSS is just switching between these two.

STEP 7

Build sections like LEGO

Here's the secret: almost every section on all 3 pages uses the same few blocks, stacked in the same order:

<section class="section">           ← 1. a band with space above & below
  <div class="container">           ← 2. keeps it centered
    <div class="section-head">      ← 3. the title of the section
      <h2>Dua Layanan Utama untuk Bisnis Anda</h2>
    </div>
    <div class="grid grid-2">       ← 4. a grid with 2 columns
      <div class="card"> ... </div> ← 5. cards inside the grid
      <div class="card"> ... </div>
    </div>
  </div>
</section>

Want a different look? Just swap a name tag:

  • section-tint → light warm grey background (we alternate off-white / grey so sections are easy to tell apart).
  • grid-2, grid-3, grid-4 → 2, 3 or 4 cards per row.
  • split → two columns: text on one side, picture on the other.
  • cta-band → the big charcoal "call to action" strip at the end of each page.
  • check-list → a list with charcoal ✓ ticks.

So we went down the plan, section by section, and for each one: pick the blocks → paste the text from the plan → done. For example, the "Cara Kerja" section uses a numbered list (<ol>) with round number circles.

Pictures we don't have yet: the plan says to use real photos (team, client work). We don't have them, so we used striped boxes saying [Foto asli tim…]. The laptop and phone in the top section are drawn with CSS boxes only, no image file. Icons are tiny drawings written as code (<svg>).

💡 Once you understand one section, you understand them all. That's why the site is easy to change later.

STEP 8

Make it work on phones ("mobile first")

The plan says most visitors come from Instagram or WhatsApp, on their phone. So we wrote all the CSS for a small phone screen first: one column, everything stacked.

Then, at the bottom of style.css, we added extra rules that only switch on for wider screens. These are called media queries:

@media (min-width: 720px) {         ← "only if the screen is at least 720px wide" (tablet)
  .grid-2 { grid-template-columns: repeat(2, 1fr); }   ← 2 columns
}

@media (min-width: 960px) {         ← laptop and bigger
  .grid-4 { grid-template-columns: repeat(4, 1fr); }   ← 4 columns
  .menu-icon { display: none; }      ← hide ☰, show the normal menu
}

Buttons in the middle on phones

On a laptop, buttons sit on the left under the text, which looks natural next to a picture. On a narrow phone, a button stuck on the left looks lopsided, so we center it. We used a media query that works the other way around, with max-width ("only screens smaller than 720px"):

@media (max-width: 719px) {
  .btn-row { justify-content: center; }   ← a row of buttons: put them in the middle
  .btn { width: fit-content;               ← button is only as wide as its text
         margin-left: auto;                ← equal empty space on the left…
         margin-right: auto; }             ← …and on the right = centered!
}

Making everything shrink smoothly (not just jump)

Media queries only change things at certain sizes. To make text, buttons and spacing shrink smoothly as the screen gets smaller, we used two more tricks:

① One "master size" that shrinks. At the top of the CSS we set the page's base text size with clamp():

html { font-size: clamp(10px, 7px + 2.4vw, 17px); }
                        ↑ never smaller than 10px
                               ↑ ideal size grows with the screen width
                                            ↑ never bigger than 17px

vw means "% of the screen width" (1vw = 1% of the width). So on a big laptop the base size is 17px, on a normal phone about 16px, and on a tiny screen it keeps getting smaller.

Then almost every size in the CSS (text, buttons, icons, circles, gaps) is written in rem, which means "times the master size". A button with padding: 0.7rem automatically gets smaller when the master size gets smaller. Change one number, and the whole page scales together.

② Nothing is allowed to poke out. A few safety rules stop content from sticking out of the screen:

body { overflow-wrap: anywhere; }   ← very long words break onto the next line
.btn { max-width: 100%; }           ← a button is never wider than the screen
.btn-row { flex-wrap: wrap; }       ← buttons move to a new line if there's no room
grid-template-columns: minmax(0, 1fr);  ← grid columns are allowed to shrink

Headings use clamp() too, so a big title gets smaller on phones instead of staying huge. Even the space between sections shrinks.

✋ Try it: press F12, turn on the phone view (Ctrl + Shift + M), and drag the width all the way down to the smallest Chrome allows. Text and buttons get smaller, and nothing should stick out the side.

✋ Try it: open the site in your browser and make the window narrow, then wide. Watch the cards jump from 1 column to 2 to 4, and the ☰ appear and disappear.

STEP 9

Clicky things, without JavaScript

The plan asked for a few interactive parts. We built all of them with HTML + CSS only, using four tricks:

① FAQ that opens and closes: <details>

HTML has a built-in "click to open" box. No tricks needed at all:

<details>
  <summary>Apakah saya perlu mengerti teknologi?</summary>  ← always visible
  <p>Tidak perlu. Kami bantu dari awal sampai selesai.</p>  ← shows when clicked
</details>

② Price tabs (Website / Media Sosial): radio buttons

Radio buttons are the round "pick only one" buttons. We hid two of them, and made the tab labels click them. CSS then says "if the Website radio is picked, show the Website cards":

#tab-web:checked ~ #panel-web { display: grid; }

The portfolio filter (Semua / Website / Media Sosial) uses exactly the same trick: picking "Website" hides cards tagged is-sosmed.

③ Portfolio pop-up: :target

A link like href="#proyek-1" jumps to the element with id="proyek-1", and the address bar ends with #proyek-1. CSS can notice that with :target:

.modal { display: none; }            ← pop-ups hidden
.modal:target { display: flex; }     ← the one in the address bar shows up

The ✕ button is just a link to #portofolio, so the pop-up is no longer the target and disappears. We used the same trick for the "Terima kasih!" message after the form is sent (#terima-kasih).

④ The "Ada pertanyaan?" bubble: CSS animation

Next to the floating WhatsApp button, a small bubble fades in after 4 seconds:

.wa-tip { opacity: 0; animation: show-tip 0.4s ease 4s forwards; }
                                ↑ wait 4 seconds, then fade in and stay
@keyframes show-tip { to { opacity: 1; } }
STEP 10

WhatsApp buttons

WhatsApp has a free special link: https://wa.me/ + phone number. When someone taps it, WhatsApp opens a chat with that number. You can even pre-type the first message:

https://wa.me/6281234567890?text=Halo%2C%20saya%20ingin%20konsultasi
             └── number ───┘      └────── the message ──────┘
  • The number starts with 62 (Indonesia) and drops the first 0: 0812… becomes 62812…
  • In links, spaces can't be written normally, so a space becomes %20, a comma %2C, a slash %2F. (Tip: search "URL encoder" online, paste your message, and it converts it for you.)

Following the plan, every button has a different message (e.g. "…tertarik dengan paket Website Starter"). That way the agency instantly knows which button the customer clicked.

The round green button in the corner uses position: fixed, which means "stay in this spot on the screen, even while scrolling".

STEP 11

The contact form

The form on the Tentang page has 5 boxes, as the plan says: Nama, Nama Bisnis, Nomor WhatsApp, Layanan, Pesan. Each box has a <label> (the visible name above it) so people always know what to type.

HTML can check the form by itself before sending:

<input type="text" name="nama" required>   ← "required" = can't be empty
<input type="tel" name="whatsapp" required pattern="(08|628|\+628)[0-9]{7,12}">
                                           ↑ must look like an Indonesian phone number

Where does the message go? HTML alone can't send email. So the form sends it to FormSubmit, a free service that forwards it to the agency's email:

<form action="https://formsubmit.co/halo@namaagensi.co.id" method="POST">
  1. Replace halo@namaagensi.co.id with the agency's real email.
  2. The first time someone sends the form, FormSubmit emails you a confirmation link. Click it once, and it works forever after.
  3. After the website is online, replace https://[domain-anda] in the hidden _next line with your real web address, so visitors come back to the "Terima kasih!" message.
STEP 12

Copy to the other pages

Once index.html was finished, building the other two pages was much faster:

  1. Copy the whole <head>, <header>, <footer> and the WhatsApp button. They're the same on every page.
  2. Change the <title> and description for that page (good for Google).
  3. Move class="active" to the current page's menu link, so it shows underlined.
  4. Fill <main> with that page's sections from the plan, using the same LEGO blocks.

Jump links: we gave some sections an id, like id="website" or id="kontak". A link to layanan.html#website opens the Layanan page and scrolls right to that section. That's how "Hubungi Kami" takes you straight to the form.

💡 Because the header and footer are copied into 3 files, if you change a menu link, change it in all 3 pages. (With only 3 pages, that's easy.)

STEP 13

Test it

  1. Open it: double-click index.html. It opens in your browser.
  2. Click everything: every menu link, every button, the tabs, the filter, the pop-ups, the FAQ.
  3. Pretend to be a phone: in Chrome or Edge press F12, then click the small phone/tablet icon (or press Ctrl + Shift + M). Pick "iPhone" or "Galaxy" at the top. Check nothing is cut off or too small.
  4. After any change: save the file (Ctrl + S), then refresh the browser (F5).
STEP 14

Replace the [placeholders]

Anything in [square brackets] is a placeholder: fake text waiting for the agency's real info. The plan is clear: only use real numbers, real photos and real testimonials. Never invent them.

Fastest way: in VS Code, press Ctrl + Shift + H (Find & Replace in all files).

Find thisReplace with
[Nama Agensi] and [Nama<span>Agensi]</span> (logo)The agency's name
6281234567890The real WhatsApp number (62 + number without the first 0)
[0812-3456-7890]The same number, written normally
halo@namaagensi.co.id and [email agensi]The real email
Rp [...] and [X]Real prices and numbers
[Alamat kantor], [@akun], [tahun], [kota]Real details
Striped photo-placeholder boxesReal photos: <img src="images/tim.webp" alt="Tim kami">
Portfolio cards marked "Contoh Desain"Real projects (or keep the label if they are demo work)

For photos: make an images folder, save pictures as .webp or small .jpg files (so the site loads fast), and always write an alt="…" description for people who can't see the image.

STEP 15

Put it on the internet

Because it's only HTML and CSS files, putting it online is easy and can be free:

  • Netlify Drop (easiest): go to app.netlify.com/drop and drag the whole practice-1 folder onto the page. You get a link in seconds.
  • GitHub Pages: upload the files to a GitHub repository and turn on "Pages" in its settings.
  • Normal hosting (Niagahoster, Hostinger, etc.): upload the files into the public_html folder.

Later you can connect your own domain (like namaagensi.co.id).

Little dictionary

WordSimple meaning
TagAn HTML word in pointy brackets, like <p>. Tells the browser "this is a paragraph".
ElementA tag together with its content: <p>Hi</p>.
AttributeExtra info inside a tag: href="…", class="…", id="…".
ClassA reusable name tag for styling. Many elements can share one.
idA unique name for one element. Used for jump links (#kontak).
SelectorThe part of CSS that picks what to style: h1, .btn, #kontak.
Property: valueOne CSS rule: color: blue; → "the color is blue".
GridA CSS way to arrange things in rows and columns.
Media queryCSS rules that only work on certain screen sizes.
ResponsiveLooks good on any screen: phone, tablet, laptop.
CTA"Call To Action": a button asking the visitor to do something, like "Chat via WhatsApp".
PlaceholderTemporary fake content, waiting to be replaced.
CommentA note for humans in the code. HTML: <!-- … -->, CSS: /* … */.
